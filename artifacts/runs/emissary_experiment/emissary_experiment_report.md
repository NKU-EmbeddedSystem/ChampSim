# EMISSARY 验证实验报告（第1轮）

## 实验目的

验证 EMISSARY 替换策略及其分区异构方案的有效性。核心假设：如果 L2 Cache 存在容量过剩（平坦区），将冗余的 SRAM 资源用于 EMISSARY 的 I-cache 保护应能带来性能提升。

## 实验配置

本实验比较 4 种 L2C 配置：

| 配置名称 | L2 Way 数 | 替换策略 | 说明 |
|----------|----------|---------|------|
| Baseline (基准) | 8 | LRU | 当前默认配置，全部用于数据缓存 |
| Phase1 (统一EMISSARY) | 8 | EMISSARY P(N) | 全部 8-way 使用 EMISSARY 替换策略 |
| Phase2 (分区异构) | 8 | LRU(4W) + EMISSARY(4W) | 4-way 数据缓存 + 4-way EMISSARY I-cache保护 |
| Extra (容量对比) | 4 | LRU | 纯容量对比基线：只用 4-way 数据缓存 |

- **仿真参数**：预热 50M 指令，仿真 500M 指令
- **测试 trace（4个）**：barnes_1, facesim_1, fft_m24, x264_1

| Trace | Baseline IPC (8W) | Extra IPC (4W) | IPC 下降 | 平坦区？ |
|-------|-------------------|---------------|---------|---------|
| barnes_1 | 2.2306 | 2.2292 | -0.1% | ✅ 是 |

## 核心结论

### 1. 统一的 EMISSARY（Phase1）完全无效

在所有 4 个 trace 上，8-way 统一 EMISSARY 相比 8-way LRU 基线，IPC 变化均为 0.00%。EMISSARY 的 I-cache 保护机制在此配置下**没有产生任何可测量的性能提升**。

### 2. 分区异构（Phase2）接近无效

分区方案（4W LRU + 4W EMISSARY）仅在 x264_1 上展现了微弱优势（相比 LRU4W 提升 0.88%），在其余 3 个 trace 上无任何提升。更重要的是，**没有任何 trace 的分区方案 IPC 能超过 8W LRU 基线**——说明拿走后 4 way 的数据缓存能力导致的 IPC 损失大于 EMISSARY 带来的收益。

### 3. 根本原因：这些 trace 没有 I-cache 压力

关键证据：
- **所有 trace 的 `decode_starvation_cycles` 均为 0**，说明前端取指从未因 I-cache miss 而停顿
- **L1I MPKI 极低**：barnes_1 和 fft_m24 的 L1I MPKI 为 0.00（L1I 命中率 100%），说明指令 cache 完全命中了 L1I
- **Branch mispredict rate 不变**：各配置间分支预测失败率完全一致，说明 EMISSARY 没有改善控制流行为

### 4. 实验意义

本轮实验说明：**EMISSARY 的有效性高度依赖于 workload 的 I-cache 压力**。对于 L1I 命中率极高或前端没有 decode starvation 的 trace，无论使用统一的 EMISSARY 还是分区方案，都无法获得性能提升。这并不否定 EMISSARY 的理论价值，但表明需要筛选**具有实际 I-cache 压力**的 trace 来进行有效验证。
